# 작업 규칙

사용자와 AI가 같이 작업할 때 지키는 규칙입니다. AI는 작업 전에 이 문서를 읽습니다. ([CLAUDE.md](../CLAUDE.md)에서 안내)

## 깃 규칙

커밋 제목은 `type: 내용` 형식입니다.

| type | 언제 |
| --- | --- |
| `fix` | 버그를 수정한 경우 |
| `feat` | 새로운 기능을 추가한 경우 |
| `docs` | 문서를 수정한 경우 |
| `test` | 테스트 코드를 추가한 경우 |
| `refactor` | 코드 리팩토링을 한 경우 |
| `style` | 코드 의미에 영향을 주지 않는 변경사항인 경우 (코드 포맷 변경, 세미콜론 추가 등) |
| `chore` | 빌드 부분 혹은 패키지 매니저를 수정한 경우 |
| `BREAKING CHANGE` | 커다란 API 변경의 경우 (API의 arguments, return 값의 변경, DB 테이블 변경, 급하게 치명적인 버그를 고쳐야 하는 경우). 본문이나 푸터의 시작 부분에 `BREAKING CHANGE: 설명`을 추가한다. 제목에 `!`를 추가해 표시할 수도 있다 |
| `comment` | 주석을 추가한 경우 |
| `rename` | 파일 혹은 폴더명을 수정하거나 옮기는 작업을 수행한 경우 |
| `remove` | 파일 혹은 폴더를 삭제한 경우 |
| `design` | css 등 사용자 UI 디자인 변경 |
| `ongoing` | 개발 진행 중 중간 저장이 필요한 경우 |
| `temp` | 임시 기능을 구현해야 하는 경우 |

- 커밋은 Fork로 한다. 첫 줄이 제목, 둘째 줄부터 본문이면 Fork가 알아서 구별한다.
- 작업은 `dev`에서 브랜치를 따서 한다. 이름은 `feature/`, `refactor/`, `chore/` 처럼 type을 앞에 둔다.
- **머지가 끝난 브랜치도 지우지 않고 남긴다.** (커밋 이력을 남기고 싶어서)
- `Packages/packages-lock.json`과 `Pretendard Dynamic SDF.asset`은 Unity가 자동으로 바꾸므로 가능하면 커밋에서 제외한다.

## 작업 규칙

### 시작 트리거 (절대 규칙)

- 사용자가 **"다음 작업 하자"**라고 말하기 전에는 작업을 시작하지 않는다.
- 그 말이 없으면 단순히 의견을 나누고 싶다는 뜻이다.
- "todo"는 다음 작업을 정리해 보자는 뜻이다. 할 일만 간단히 정리하고 작업(파일 표, 수정 코드 등)은 만들지 않는다.

### 작업 정리 형식

"다음 작업 하자"라고 하면 아래 형태로 정리한다.

1. **수정/추가될 파일 목록**: 표로 만든다. 왼쪽은 해당 프로젝트 폴더(Manager, Network 등)만 알 수 있게, 오른쪽에는 파일명을 넣는다. 추가하는 파일은 사용자가 작업 시작 전에 먼저 만들 수 있게 표시한다.
2. **수정되는 스크립트**: 수정하는 만큼 사용자가 알아볼 수 있어야 한다. 핵심은 **"~ 함수 밑에", "~ 주석 위에"처럼 위치를 자세하게** 알려 주는 것이다. 테스트처럼 파일 양이 많으면 파일 통째로 올린다.
3. **커밋 내용**: 첫 줄 제목, 둘째 줄부터 본문. 제목과 본문을 합쳐서 줘도 된다.
4. **다음 작업 요약**: 다음 작업을 간단히 정리한다. 사용자가 이걸 보고 다음 작업에서 PR을 쓸지 계속 작업할지 정한다.
5. **완성된 파일**: 이번 작업에서 추가된 완성 파일을 올린다. README와 기획서 같은 문서는 부분이 아니라 **풀버전**으로 올린다.
6. **PR 안내** (사용자가 PR을 올리겠다고 한 경우에만)
   - 작업 브랜치명을 알려 주면 개인 포크 안 PR 주소를 만든다: `https://github.com/vmffpdlwnd/Our_Marble/compare/dev...작업브랜치?expand=1`
   - 열린 화면에서 **base repository가 `vmffpdlwnd/Our_Marble`인지** 확인하라고 상기시킨다.
   - PR 제목과 본문은 3번(커밋 내용)과 4번(다음 작업 요약)을 바탕으로 쓴다.

### 그 밖의 약속

- 작업이 끝나면 [`작업현황.md`](작업현황.md)를 갱신해서 5번 완성 파일에 포함한다.
- 파일을 추가, 이동, 삭제했으면 [`CLAUDE.md`](../CLAUDE.md)의 코드 지도도 같이 갱신한다.
- `.jslib` 파일은 파일 카드가 안 보일 수 있어서 `.jslib.txt` 사본으로도 올린다.
- Unity 에디터와 웹 빌드는 AI가 돌릴 수 없다. 동작 확인은 사용자가 하고, AI는 확인하지 못했다고 밝힌다.
