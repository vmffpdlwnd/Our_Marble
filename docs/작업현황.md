3단계 확인 방법 (에디터와 웹 빌드 두 개로, 서로 다른 계정)
- 참가자가 게임 중 나가기 → 로비에서 방을 새로 만들 수 있다. 목록에 그 게임이 `[이어하기]`로 보이고 누르면 자리로 돌아간다. 남은 사람의 게임은 그 사람을 AFK로 대신 진행한다
- 방장이 게임 중 나가기 → 남은 사람이 방장을 이어받아 게임이 계속된다. 나간 방장은 새 방을 만들 수 있다
- 파산한 뒤 나가기 → 확인 창이 "다시 들어올 수 없어요"로 뜬다. 로비에 `[이어하기]`가 없다. 방 코드로 들어가려 해도 "파산해서 이 게임에 다시 들어올 수 없어요"로 거절된다
- 혼자 하기(오프라인)에서 게임 중 나가기 → 로비에서 방을 새로 만들 수 있다

주사위 결과 판정에서 정한 것 (1번)
- 비교 순서: 도착 칸 등급(좋음 > 보통 > 나쁨) → 둘 다 남의 땅이면 통행료가 적은 쪽 → 월급을 받는 쪽 → 한 번 더 굴리는 쪽(더블). 그래도 같으면 먼저 굴린 쪽을 쓴다.
- 나쁨: 남의 땅, 무인도(탈출 실패, 3연속 더블 포함), 세무조사. 좋음: 빈 땅, 내 땅, 황금열쇠, 세계여행, 적립금. 보통: 출발 칸에 멈춤.
- 무인도, 세무조사와 남의 땅은 같은 나쁨이다. 통행료는 둘 다 남의 땅일 때만 비교한다. (기획서의 "통행료가 클수록 나쁨"은 남의 땅끼리의 비교)
- 통행료는 통행료 카드(면제권, 반값권) 할인 전 금액으로 본다. 카드를 쓸지는 도착한 뒤에 정하기 때문이다.
- 무인도 탈출 더블은 추가 턴이 없으므로 "한 번 더 굴림"으로 치지 않는다. (`GameRules.ApplyDice`와 같음)
- 미리 보기(`PreviewRoll`)는 `GameRules.ApplyDice`와 같은 순서로 판단하고 상태를 바꾸지 않는다. ApplyDice를 고치면 같이 고친다.

### v1.4 (접속 규칙, 서버 전적 관리, 판 조작 방지)

PlayFab 서버 함수(CloudScript 등)를 새로 쓴다. 어떤 방식이 되는지, 무료 범위는 시작할 때 조사한다. 네트워크 버전은 접속 규칙(1, 2번)을 고칠 때 한 번 올린다.

| 순서 | 할 일 | 상태 |
| --- | --- | --- |
| 1 | **접속 규칙 1: 로그인은 한 기기에서만.** 다른 기기에서 같은 계정으로 로그인해 로비에 들어오면, 먼저 있던 기기는 연결이 끊기고 로그인 화면으로 간다. 같은 컴퓨터의 웹과 exe도 다른 기기로 본다. (지금은 막지 않아서, 한 계정으로 두 판을 동시에 하거나 같은 판에 두 기기가 들어가 한쪽 화면이 멈춘 것처럼 된다) | |
| 2 | **접속 규칙 2: 한 사람은 게임 하나에만.** 게임이 끝나기 전까지는 그 게임의 재접속을 계속 제공하고, 다른 게임에는 들어갈 수 없다. 다른 기기에서도 이어할 수 있게, 진행 중인 방을 기기가 아니라 계정에 기억한다. (지금은 그 기기의 `PlayerPrefs`에만 있어서 다른 기기에는 이어하기가 안 보이고, 방 코드를 알면 다른 게임에도 동시에 들어갈 수 있다) | |
| 3 | **이메일 변경.** 이메일 계정에서 연결한 이메일을 바꿀 수 있게 한다 (지금은 한 번 연결하면 바꿀 수 없어서, 잘못 넣으면 "새 계정으로 시작"해야 한다). 새 이메일이 이미 다른 계정에 연결돼 있으면 "사용 중인 이메일이에요"로 알리고 바꾸지 않는다. 아니면 바꾸고 "변경했어요. 메일을 확인해 주세요"로 새 이메일의 확인 메일을 보게 한다. PlayFab에서 로그인 이메일을 바꾸는 방법(클라이언트 API로 되는지, 서버 함수가 필요한지)은 시작할 때 조사한다. 새 이메일을 잘못 넣으면 다시 로그인할 수 없게 될 수 있으니, 확인 메일을 확인하기 전까지 옛 이메일을 유지할지도 그때 정한다 | |
| 4 | **전적은 호스트가 관리.** 게임이 끝나면 각자 자기 전적을 쓰지 않고, 호스트가 참가자 모두의 결과(플레이, 승리)를 한 번에 보고한다. 클라이언트는 전적을 직접 쓰지 못하게 막는다. 클라이언트 API로는 남의 통계를 쓸 수 없으므로 PlayFab 서버 함수(CloudScript 등)가 필요하다. 서버 함수 방식과 기존 전적 처리(그대로 둘지, 새로 셀지)는 시작할 때 정한다. 나간 사람도 호스트가 같이 올리므로 탈주해도 패배가 남는다 (지금은 끝날 때 남아 있는 사람만 자기 결과를 올려서, 나가면 패배가 안 남는다) | |
| 5 | **봇전은 전적 없음.** 시작할 때 사람이 1명이면 봇전으로 보고 기록하지 않는다. (봇전은 호스트가 그 PC라 나가면 방과 게임이 함께 사라져, 재접속과 다른 기기 이어하기도 원래 안 된다) | |
| 6 | **접속 중 AFK와 탈주 구별.** 호스트가 AFK인 이유를 같이 기억한다 (연결이 끊김 / 제한 시간 초과). 판이 끝날 때 연결이 없는 사람(탈주)은 패배로 기록한다. 접속 중 AFK는 AFK로 대신 진행된 비율이 기준을 넘으면 그 판에서 봇 취급(기록 없음)이고, 봇 취급을 빼고 플레이한 사람이 2명 미만이면 판 전체를 기록하지 않는다. 기준(예: 50%)은 그때 정한다. 방장도 같은 규칙이다 | |
| 7 | **맞대조.** 호스트와 참가자가 각자 판 번호와 결과(그리고 자기가 직접 한 차례 수)를 서버 함수에 보내고, 다르면 그 판은 무효다. 보고가 안 온 사람은 비교에서 뺀다. 2명 판에서 한 명만 보냈으면 대조할 수 없어 무효다 | |
| 8 | **경고와 정지.** 무효가 난 판에서 3명 이상이면 다수와 다른 사람(소수)만 경고 횟수를 올리고, 2명 판은 누가 틀렸는지 알 수 없어 무효만 한다. 횟수는 서버만 쓰는 계정 데이터에 쌓고, 정한 횟수를 넘으면 PlayFab 계정 정지(기간 지정)를 건다. 정지된 계정은 연결 실패와 다르게 "계정이 N시간 동안 정지됐어요"로 안내한다. 횟수와 시간은 그때 정한다 | |

호스트가 게임 진행 자체(주사위, 카드)를 조작하는 것은 규칙을 서버가 돌려야 막을 수 있어 범위 밖이다.

### 정하지 않은 것

- 방장 치팅과 전적 조작 방지 (나중에 넣을 계획. 배포 범위를 넓힐 때 서버 쪽 검증을 검토)

## 알려진 점

- 웹 한글 입력은 HTML 입력칸을 겹치는 방식이라, 화면의 커서가 실제 위치와 다르게 보일 수 있다. (구현 방식에서 예상한 것이고 확인하지 못했다) 모바일 브라우저는 이 방식을 쓰지 않고 확인하지 않았다.
- 웹 채팅은 보내기 버튼으로 보내면 겹친 입력칸이 닫혀서, 다시 눌러야 이어서 칠 수 있다. (엔터로 보내면 이어서 칠 수 있게 만들었다)
- 웹 방 코드 복사는 Safari와 모바일을 확인하지 않았다. 막히면 복사 대신 코드가 화면에 보인다.
- 웹에서 `WebGLInput.captureAllKeyboardInput`을 꺼서, 캔버스를 한 번 클릭해야 키 입력이 게임으로 간다.
- 대기방과 방 목록 안의 사람 닉네임과 사람이 정한 방 이름은 번역하지 않는다. 봇 이름("봇 1" ~ "봇 4")만 번역표에 있다. (`Loc.TName`)
- 대기방에서도 설정창을 열 수 있다(v1.3). 대기방이 열려 있는 동안 언어를 바꾸는 경우는 따로 처리하지 않아서, 일부 글은 다음에 들어올 때 현재 언어로 그려진다.
- 게임 종료 사유(`남은 플레이어가 1명입니다` 등), 호스트 상태 검사, 봇 판단 로그는 개발용이라 번역하지 않는다.
- 황금열쇠 0번(무인도 표류)과 4번(손 미끄러짐) 설명의 `‘ ’`와 `—`는 설명 글꼴(Maplestory, 미리 구운 글자만 씀)에 없어서 대체 글꼴(Pretendard)로 그려진다.
- 통행료 2배를 붙인 땅은 칸 이름(빨간 굵은 글씨와 x2)으로만 보인다(v1.3.1). 따로 붙인 표시 오브젝트는 없다. 땅 고르기 완료 버튼 글자는 "여행지 선택 완료" 그대로다. (프리팹 작업 필요)
- 코드가 만드는 글 중 숫자나 값이 끝에 붙은 글("봇 3", "처리하지 못했어요 (오류 이름)")은 앞부분만 번역한다. 번역표에 앞부분이 있어야 한다. (`Loc.TryPattern`)

## 결정한 것

- **점검 중에는 게임 중인 사람만 면제한다 (v1.3.2).** 로비와 대기방에 있는 사람은 모두 점검을 알아야 하고, 점검 중에는 새 게임을 시작할 수 없다. 이미 시작한 게임은 끝까지 하고 전적도 남긴다.
- **v1.3.2는 버그 수정, 자리 비움 버튼, 후보 로그이고 네트워크 버전 5 그대로. v1.4는 접속 규칙, 서버 전적 관리, 판 조작 방지이고 서버(PlayFab 서버 함수)를 쓴다.** 네트워크 버전은 v1.4 접속 규칙을 고칠 때 한 번 올린다.
- **전적은 호스트가 관리한다 (v1.4).** 각 클라이언트가 자기 전적을 쓰지 않고, 호스트가 참가자 모두의 결과를 보고한다. 호스트가 결과를 조작하는 것은 v1.4의 맞대조로 막는다. 봇전은 기록하지 않고, 정보가 다르면 그 판은 무효이며, 무효가 쌓이면 경고와 정지를 건다.
- **접속 규칙 (v1.4):** 로그인은 한 기기에서만 된다(나중에 로그인한 기기가 이기고, 먼저 기기는 로그인 화면으로). 웹과 exe는 같은 컴퓨터여도 다른 기기다. 한 사람은 게임 하나에만 들어갈 수 있고, 그 게임이 끝나기 전까지 어느 기기에서든 재접속할 수 있다. (작업현황 v1.4 1, 2번)

- 서버 점검과 구버전은 **온라인을 끄고 혼자 하기로 시작**한다. 전용 서버가 없어서 PlayFab Title Data(`Maintenance`)를 점검 표시로 쓰고, 버전은 `NetworkVersion` 정수로 비교한다. 이미 방이나 게임 안에 있는 사람은 끊지 않는다. (기획서 "점검과 구버전")
- 게임 중 나가기는 방장에게 나간다고 알리지 않고 **연결만 끊는다.** 방장은 연결이 끊긴 사람처럼 자리를 남기고 AFK로 대신 진행한다. 그래서 파산하지 않은 사람은 이어하기로 돌아올 수 있다. 혼자 하기에서는 이 PC의 방과 게임을 버린다
- 파산한 사람은 나가기뿐 아니라 **연결이 끊겨도 다시 들어올 수 없다.** 방장이 자리를 돌려줄 때 파산 여부만 보기 때문이다. (관전 중이라 잃는 것이 없어서 그대로 둔다)

- 영문화는 영어 전용 빌드가 아니라 **한/영 전환**이다. 전환은 설정창에서 하고, 로그인 씬에도 설정 버튼을 넣는다. (설정창은 로비와 게임이 같은 프리팹을 쓴다)
- 땅 이름(지명 23곳)과 황금열쇠 카드 이름과 설명도 번역한다. 번역표에 `서울 → Seoul`처럼 적는다.
- 다른 화면이나 요청에 넘기거나 값을 찾는 데 쓰는 글(맵 이름 등)은 번역하지 않는다. 화면에 보여 줄 때만 번역한다. (`LobbyManager.MapKey`는 값, `MapName`은 표시용)
- 번역표는 한국어 문장을 키로 쓰고 `Assets/Resources/Localization/en.txt`에 둔다. 번역이 없는 글은 한국어로 보이고, 에디터에서는 콘솔에 경고가 뜬다.
- 기본 언어는 고른 적이 없으면 브라우저와 OS 언어를 따른다. (한국어면 한국어, 그 외는 영어)
- 로그인 씬의 설정창은 로비와 같은 프리팹을 그대로 쓴다. (소리 항목도 같이 보인다)
- 옛 임시 로비(`LobbyManager_temp.cs`, `LobbyScene_old.unity`)는 영문화 1단계에서 같이 정리한다. `LobbyScene_old`만 이 스크립트를 쓰고 빌드에는 들어가지 않으므로, 둘을 짝으로 지운다.
- 번역표에 빠진 글은 `tools/check_translations.py`로 찾는다. 영문화 작업을 올리기 전에 돌려서 빠진 글이 0개인 것을 확인한다.
- 선턴 결정은 지금 코드의 무작위 방식을 유지한다.
- 웹 전용 코드는 `#if UNITY_WEBGL && !UNITY_EDITOR`와 `Plugins/WebGL`로 분리해 Windows와 에디터를 바꾸지 않는다.
- 파일 위치 안내는 줄 번호가 아니라 함수와 주석 이름으로 한다.
- 영문화는 v1.2와 따로 **v1.1.3**으로 배포했다. 영문화 PR은 끝에 한 번에 올렸다. (PR #27)
- 파산 신청은 **내 차례에 입력을 기다리는 동안만** 할 수 있다. (단계는 가리지 않는다) 호스트는 차례인 사람의 요청만 받고 클라이언트는 알림을 차례대로 처리하는 구조라, 남의 차례 중 신청은 받지 않는다.
- 파산 신청한 사람의 재산은 **은행으로** 간다. 땅은 주인 없음 + 땅 단계로 돌아가고 현금은 0이 된다. 등수는 통행료 파산과 같이 그 시점의 생존자 수이고, 더블이어도 다음 사람에게 넘어간다.
- "포기"는 따로 만들지 않고 **파산 신청 하나**로 합친다. 파산한 사람은 게임에 남아 관전하고, 파산한 뒤 나가면 다시 들어올 수 없다. 게임 중 나가기(자리를 남기고 AFK로 대신 진행, 이어하기로 복귀)는 파산하지 않은 사람에게는 그대로다.
- 파산 신청 알림을 넣으면서 네트워크 버전을 3에서 4로 올렸다. (옛 빌드는 이 알림을 모른다)
- 황금열쇠 카드의 이름과 설명은 **팀 프로젝트 서버의 `cards.json`** 을 따른다. 원문의 `‘ ’`와 `—`도 그대로 쓴다.
- 통행료 면제 같은 보유형 카드는 나중에 넣는다. `CardEffectType`의 해당 주석과 `PlayerState.HeldCardIds`는 그때 쓸 자리로 남겨 둔다.
- 황금열쇠는 **즉발형**과 **보관형** 두 갈래로 나눈다. v1.2에서는 즉발형을 늘린다.
- 카드의 이동 목적지는 칸 번호가 아니라 **칸 종류**로 정한다. (새 스테이지 보드에서도 맞게)
- 통행료 2배는 보관형이 아니라 **즉발형**이다. 얻자마자 내 땅을 고르고, 한 번 받으면 사라진다.
- **관광지 줄 보너스:** 관광지를 가진 사람은 같은 줄의 자기 땅 통행료가 1.5배. 남의 땅에는 적용되지 않는다. 2배 표시와 곱해 최대 3배이고, 그다음 내는 사람의 면제권이나 반값권을 적용한다. 배율은 `GetToll` 한 곳에서 계산해 매각, 파산, 인수, 봇 판단도 같은 금액을 쓴다.
- 보관형 카드 에셋 14~19번은 인스펙터 대신 파일로 만들었다. (이름과 설명이 번역표 키와 한 글자도 달라지지 않게) 건설 할인 비율은 카드의 `amount`(퍼센트) 50으로 정했다.
- 보관형은 모두 1회용, 종류마다 1장이다. 사람은 쓸 때마다 고르고(턴 타이머, 시간 지나면 안 씀), 봇과 AFK는 항상 쓴다. 월급 2배만 자동이다.
- 인수 방지권을 쓰면 인수가 막히고, 인수하려던 사람은 통행료만 낸다. (면제권이나 반값권을 썼다면 그 금액 그대로)
- 위치 바꾸기는 벌칙 카드라 **둘 다 칸 효과가 없다.** 무인도만 예외로 남은 턴을 넘겨받고(0이면 3), 세계여행 예정은 사라지며 보상은 없다. 세계여행은 도착할 때 표시를 켜는 방식으로 바꿨다.
- 카드마다 다른 동작이 필요하면 카드 SO에 칸을 늘리지 않고 **효과 종류를 추가한다.** (카드를 만들 때 확인할 칸이 늘지 않게)
- 황금열쇠 알림과 요청을 바꿨지만 **네트워크 버전은 4 그대로** 둔다. 4는 아직 배포 전이라 v1.2를 배포할 때 함께 나가고, 배포된 v1.1.3(3)과는 이미 구분된다.
- 모든 스테이지는 **같은 칸 수의 정사각형 보드**로 만든다. 관광지 줄 보너스는 이걸 전제로 줄을 보드 칸 수 ÷ 4로 나눈다.
- 카드 에셋은 인스펙터에서 고친 뒤 **File → Save Project**를 해야 파일에 저장된다. (안 하면 커밋에 빠진다)
- **새 스테이지(2맵)는 가상 프랜차이즈 거리**다. 보드 한 줄이 음식 한 종류(치킨, 피자, 버거, 디저트)이고, 관광지는 카페와 빵집이다. 가게 이름은 실제 브랜드를 비튼 가상 이름이고, 그림에는 실제 로고나 글자를 넣지 않는다.
- 2맵 땅 id는 **200 + 칸 번호**다. (`PropertyData.MapId = id / 100`) 칸 배치와 금액은 1맵과 같게 시작하고, 균형은 플레이해 보고 고친다.
- 맵 번호는 로비 `LobbyManager.Maps`의 순서와 같다. 2맵은 비어 있던 "해변 마을" 자리(2번)를 쓴다.
- v1.3은 순위 보정과 뉴비 옵션이다. 남에게 직접 영향을 주는 장치(인수 금지, 통행료 할인 등)는 넣지 않는다. 주사위는 숫자가 아니라 결과(도착 칸 1순위, 더블 2순위)로 좋고 나쁨을 판단한다. 1등이면 1등 패널티가 뉴비 혜택보다 먼저다(3연속 더블 무인도 면제만 남음). 뉴비 판의 승리도 승리로 센다.
