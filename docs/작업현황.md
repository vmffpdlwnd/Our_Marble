## 알려진 점

- 웹 한글 입력은 HTML 입력칸을 겹치는 방식이라, 화면의 커서가 실제 위치와 다르게 보일 수 있다. (구현 방식에서 예상한 것이고 확인하지 못했다) 모바일 브라우저는 이 방식을 쓰지 않고 확인하지 않았다.
- 웹 채팅은 보내기 버튼으로 보내면 겹친 입력칸이 닫혀서, 다시 눌러야 이어서 칠 수 있다. (엔터로 보내면 이어서 칠 수 있게 만들었다)
- 웹 방 코드 복사는 Safari와 모바일을 확인하지 않았다. 막히면 복사 대신 코드가 화면에 보인다.
- 웹에서 `WebGLInput.captureAllKeyboardInput`을 꺼서, 캔버스를 한 번 클릭해야 키 입력이 게임으로 간다.
- 설정창의 배경음과 효과음은 값만 저장하고 효과가 없다. 오디오 파일과 사운드 시스템이 아직 없다.
- 대기방과 방 목록 안의 사람 닉네임과 사람이 정한 방 이름은 번역하지 않는다. 봇 이름("봇 1" ~ "봇 4")만 번역표에 있다. (`Loc.TName`)
- 대기방은 설정창을 열 수 없는 화면이라, 열려 있는 동안 언어가 바뀌는 경우는 따로 처리하지 않았다. 다음에 들어올 때 현재 언어로 그려진다.
- 게임 중에 언어를 바꾸면 보드 칸의 이름은 다음 게임부터 바뀐다. (칸 이름은 게임이 시작될 때 한 번 그린다)
- 게임 종료 사유(`남은 플레이어가 1명입니다` 등), 호스트 상태 검사, 봇 판단 로그는 개발용이라 번역하지 않는다.
- 코드가 만드는 글 중 숫자나 값이 끝에 붙은 글("봇 3", "처리하지 못했어요 (오류 이름)")은 앞부분만 번역한다. 번역표에 앞부분이 있어야 한다. (`Loc.TryPattern`)

## 결정한 것

- 영문화는 영어 전용 빌드가 아니라 **한/영 전환**이다. 전환은 설정창에서 하고, 로그인 씬에도 설정 버튼을 넣는다. (설정창은 로비와 게임이 같은 프리팹을 쓴다)
- 땅 이름(지명 23곳)과 황금열쇠 카드 이름과 설명도 번역한다. 번역표에 `서울 → Seoul`처럼 적는다.
- 다른 화면이나 요청에 넘기거나 값을 찾는 데 쓰는 글(맵 이름 등)은 번역하지 않는다. 화면에 보여 줄 때만 번역한다. (`LobbyManager.MapKey`는 값, `MapName`은 표시용)
- 번역표는 한국어 문장을 키로 쓰고 `Assets/Resources/Localization/en.txt`에 둔다. 번역이 없는 글은 한국어로 보이고, 에디터에서는 콘솔에 경고가 뜬다.
- 기본 언어는 고른 적이 없으면 브라우저와 OS 언어를 따른다. (한국어면 한국어, 그 외는 영어)
- 로그인 씬의 설정창은 로비와 같은 프리팹을 그대로 쓴다. (소리 항목도 같이 보인다)
- 옛 임시 로비(`LobbyManager_temp.cs`, `LobbyScene_old.unity`)는 영문화 1단계에서 같이 정리한다. `LobbyScene_old`만 이 스크립트를 쓰고 빌드에는 들어가지 않으므로, 둘을 짝으로 지운다.
- 번역표에 빠진 글은 `tools/check_translations.py`로 찾는다. 영문화 작업을 올리기 전에 돌려서 빠진 글이 0개인 것을 확인한다.
- 선턴 결정은 지금 코드의 무작위 방식을 유지한다.
- 웹 전용 코드는 `#if UNITY_WEBGL && !UNITY_EDITOR`와 `Plugins/WebGL`로 분리해 Windows와 에디터를 바꾸지 않는다.
- 파일 위치 안내는 줄 번호가 아니라 함수와 주석 이름으로 한다.
- 영문화는 v1.2와 따로 **v1.1.3**으로 배포했다. 영문화 PR은 끝에 한 번에 올렸다. (PR #27)
