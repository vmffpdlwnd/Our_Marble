# 우리의 마블 포지 기획서

> 원본 [Our-Marble/our-marble-client](https://github.com/Our-Marble/our-marble-client)를 포크해서, **별도 서버 없이 방장이 게임 규칙을 돌리는 멀티플레이**(Photon Fusion Shared 모드)로 바꾸는 프로젝트입니다.

**현재 상태:** v1.1.3 배포 완료 (웹, Windows). 멀티플레이(Photon Fusion Shared 모드)와 계정·전적(PlayFab)을 쓸 수 있고, 방 코드로 입장하고 방 이름을 정하며, 이메일 가입은 메일에서 비밀번호를 정하는 2단계입니다. ([게임 페이지](https://vmffpdlwnd35.itch.io/our-marble)) 웹에서도 한글을 직접 칠 수 있고 방 코드를 복사할 수 있습니다. 한국어와 영어를 설정창에서 바꿀 수 있습니다.

## 1. 한 줄 요약

"모두의 마블"을 모티브로 한 2~4인 온라인 보드게임을, **게임 파일 하나만 켜면 친구와 바로 할 수 있게** 만든다.

## 2. 목표와 범위

### 목표
- 자체 서버 프로그램과 Redis 없이 방장이 방을 만들고 친구가 들어오는 멀티. 계정과 전적은 외부 서비스(PlayFab)를 쓴다
- 원본의 화면·연출·규칙은 최대한 그대로 유지
- 무료 범위(Photon Fusion 무료 20 CCU, PlayFab) 안에서 운영. (한도와 요금은 바뀔 수 있으므로 사용 전에 각 대시보드에서 확인)

### 포함
- 타이틀, 로비(방 목록), 대기방(준비, 방 설정), 인게임, 결과 화면
- 주사위 이동, 땅 구매·건설·통행료·인수·매각·파산
- 월급, 세무조사, 적립금, 황금열쇠, 세계여행, 무인도, 3연속 더블
- 봇 (기본형)
- 닉네임만 입력해 바로 시작하는 익명 계정(PlayFab), 원하면 이메일 계정으로 올리기 (가입은 메일에서 비밀번호를 정하는 2단계, 로그인, 비밀번호 찾기)
- 전적 (플레이 횟수, 승리 횟수)
- 재접속 (대기방이나 게임 중에 끊긴 사람이 같은 방에 자동으로 다시 들어가고, 게임 중이었다면 방 목록의 이어하기로도 현재 상태로 복구)
- 방장 승계 (방장이 나가면 입장 순서대로 다음 사람이 방장이 되고 진행 중이던 게임을 이어감)
- 오프라인(혼자 하기): Photon이나 PlayFab에 연결하지 못하면 이 PC 안에서 봇과 하는 모드로 전환
- Windows(.exe) 배포: 웹과 같은 방에서 함께 플레이할 수 있고, 창이 뒤로 가도 계속 실행되므로 방장에게 권장
- 한/영 전환 (v1.1.3): 설정창에서 언어를 고르고, 로그인 화면에도 설정 버튼이 있다. 번역표는 `Assets/Resources/Localization/en.txt`.

### 제외
- Java 서버, Redis, JWT 로그인, 이메일 인증 코드(원본 방식), 전적 DB (전적은 PlayFab 통계로 대체)
- 방장을 직접 다른 사람에게 넘기는 기능 (Shared 모드에서는 방장이 나갈 때만 바뀐다)

### 후순위
- 성향별 봇: 기본형을 먼저 만들고, 나머지는 나중에
- 파산 신청과 포기 기능 (v1.2 예정): 플레이어가 스스로 파산을 선언하거나 게임을 포기하는 기능. 돈이 모자라 자동으로 파산하는 처리는 포함
- 황금열쇠 종류 추가 (v1.2 예정)
- 초기 컨셉 스테이지 (v1.2 예정): 지명 대신 가상의 프랜차이즈를 쓰는 새 보드 (새 보드와 땅 데이터가 필요)
- 선턴 결정 방식: 원본은 무작위 없이 방 참가 순서대로 시작하고 방장이 첫 차례지만, 지금 코드의 무작위 방식을 유지하기로 했다.

### 웹(WebGL)과 Shared 모드
- 웹에서는 Photon이 **Shared 모드를 권장**한다. Host 모드는 WebGL에서 기본으로 꺼져 있고, 연결이 자주 끊기고 항상 중계 연결을 쓴다고 공식 문서에 적혀 있다.
- 브라우저는 스레드가 하나라서, 방장 브라우저가 호스트 서버 역할을 하는 방식(Host 모드)은 부담이 크다. 그래서 Shared 모드를 쓴다.

### 웹(WebGL) 전용 처리
- Unity 웹 빌드는 브라우저의 한글 입력기(IME) 조합 입력을 입력칸에 전달하지 못한다. 입력칸을 누르면 그 위에 투명한 HTML 입력칸을 겹쳐 브라우저가 조합을 처리하게 하고, 칠한 글자를 Unity 입력칸에 실시간으로 넘긴다. (`WebIMEInput.cs`, `Assets/Plugins/WebGL/WebIMEInput.jslib`)
- Unity 웹 빌드는 시스템 클립보드를 지원하지 않는다. 보이지 않는 textarea를 선택해 브라우저에 복사를 시킨다. (`ClipboardCopy.cs`, `Assets/Plugins/WebGL/WebClipboard.jslib`)
- 두 처리 모두 `#if UNITY_WEBGL && !UNITY_EDITOR`와 `Plugins/WebGL` 폴더로 분리해서 Windows(.exe)와 에디터는 기존 동작 그대로다. 모바일 브라우저는 입력 처리를 바꾸지 않는다.

### 한/영 전환
- 한국어 문장이 곧 번역표의 키다. 번역표(`Assets/Resources/Localization/en.txt`)에 "한국어 문장, 탭, 영어 문장"으로 적고, 번역이 없는 글은 한국어로 보인다. 에디터에서는 빠진 글을 콘솔에 경고한다.
- 코드가 만드는 글은 `Loc.T("문장", 값)`이나 `Loc.Bind(글자칸, "문장")`으로 번역하고, 씬과 프리팹에 적힌 한국어 글자는 씬이 열릴 때 `Loc.AutoLocalize`가 찾아 묶는다. (`LocalizedText`가 언어가 바뀔 때 다시 번역한다)
- 사람이 정한 글(닉네임, 방 이름)은 `Loc.TName`으로 번역표에 있는 것(봇 이름)만 번역한다. 보드 칸처럼 좁은 곳은 `Loc.TShort`와 번역표의 `칸:한국어 문장`으로 짧은 영어를 쓴다. 등수는 `Loc.Rank`(1st, 2nd)로 만든다.
- 값이 끝에 붙은 글("봇 3", "처리하지 못했어요 (오류)")은 앞부분만 번역한다. 다른 화면이나 요청에 넘기는 값(맵 이름 등)은 번역하지 않고 보여 줄 때만 번역한다.
- 고른 언어는 `PlayerPrefs`에 저장하고, 고른 적이 없으면 브라우저와 OS 언어를 따른다. (한국어면 한국어, 그 외는 영어) 빠진 글은 `tools/check_translations.py`로 찾는다.

### Photon 무료 한도
- 무료 20 CCU는 **Fusion/Quantum 전용, 계정당 앱 하나**
- CCU는 방 단위가 아니라 전체 동시접속자 수. 방당 4명이면 약 5방
- 앱 ID를 여러 개 만들어 한도를 합치는 방식은 쓰지 않는다
- 가격 정책은 바뀔 수 있으므로 실제 사용 전에 Photon 대시보드에서 확인

### PlayFab (계정, 전적)
- 로그인: 브라우저에 저장한 무작위 값으로 익명 로그인한다. 처음이면 계정이 자동으로 만들어진다.
- Photon 접속은 PlayFab이 준 토큰으로 인증하고, Photon이 보는 사용자 ID가 PlayFab ID가 된다. (Photon 대시보드의 Custom Server 인증과 PlayFab의 Photon 애드온 설정이 필요하다. 설정 방법은 README)
- SDK 대신 REST를 직접 부른다. 웹(WebGL)에서 쓸 수 있는 SDK가 분명하지 않았고, 필요한 API가 몇 개뿐이라서다. 웹 빌드에서의 동작은 v1.1에서 확인했다.
- 비밀 키(Secret Key)는 코드와 저장소에 두지 않는다. Title ID는 공개돼도 된다.
- 가격과 한도는 바뀔 수 있으므로 실제 사용 전에 PlayFab 쪽에서 확인한다.

## 5. 구조

### 호스트 권위 방식 (Shared 모드)
- Photon Shared 모드에는 서버도 호스트 플레이어도 없다. 대신 방마다 **마스터 클라이언트** 한 명이 정해진다. 우리는 마스터를 방장으로 쓰고, 게임 규칙 판정, 봇, 시간을 맡기는 이 역할을 이 문서에서 **호스트**라고 부른다.
- 마스터는 방을 만든 사람이 처음 맡고, 나가면 **들어온 순서대로 가장 오래 남은 사람**이 맡는다. 마스터를 직접 지정할 수는 없다.
- 방장 클라가 주사위, 구매 검증, 통행료, 턴 진행을 처리하고 결과를 전원에게 보낸다.
- 참가자는 "주사위 굴릴게요", "구매할게요" 같은 **요청만 보내고 결과만 받는다.**
- 서버 시절의 "요청 → 검증 → 결과 알림" 흐름을 그대로 유지한다.

### 방과 방 코드
- 방 하나는 Photon 세션 하나다. 세션 이름이 방 코드이고, 헷갈리는 글자를 뺀 31글자 중에서 무작위 8자리로 만든다. 화면에는 `ABCD-EFGH`처럼 보여 준다.
- 방을 만들 때 방장이 인원, 맵 같은 목록용 정보를 함께 정한다. (Photon 로비는 방을 만들 때 정한 정보만 목록에 보여 주기 때문)
- 로비 방 목록은 Photon 세션 중 **방장 PC가 호스트를 돌리는, 대기 중인 방**만 보여 준다. 내가 하던 게임 방만 `[이어하기]`로 함께 보인다.
- Photon 방의 최대 인원은 만든 뒤에 못 바꿔서 4로 두고, 실제 자리는 게임 규칙(인원 − 봇)이 막는다. 대기 중에 자리가 다 차면 방을 닫는다. **게임 중에는 닫지 않는다.** 닫힌 방에는 돌아오는 참가자도 못 들어오기 때문이고, 참가자가 아닌 사람은 방장이 들여보내지 않는다.
- 방을 보는 쪽과 만드는 쪽의 네트워크 버전이 다르면 서로의 방이 보이지 않는다. (현재 3) 접속 지역은 한국(kr)으로 고정했다.

### 요청 (참가자 → 방장)

| 요청 | 내용 | 허용 단계 |
| --- | --- | --- |
| 주사위 굴리기 | 없음 | 굴리기 대기 |
| 세계여행 목적지 | 목적지 칸 번호 | 목적지 대기 |
| 황금열쇠 뽑기 | 없음 | 카드 대기 |
| 땅 구매·거절 | 땅 번호, 수락 여부 | 구매 대기 |
| 건설·거절 | 땅 번호, 수락 여부 | 건설 대기 |
| 인수·거절 | 땅 번호, 수락 여부 | 인수 대기 |
| 매각 | 팔 땅 번호 목록 | 매각 대기 |
| 상태 요청 (재접속) | 없음 | 제한 없음 |

### 알림 (방장 → 전원)

주사위 결과, 목적지 선택, 카드 결과, 구매·건설·인수 결과, 매각 결과, 상태 동기화(재접속자에게만).

요청과 알림은 Photon의 **신뢰할 수 있는 데이터 전송**(reliable data)으로 보낸다. (RPC 하나는 약 512바이트까지라서 방 정보와 상태 동기화 같은 큰 메시지에 맞지 않는다.) 보내는 쪽이 번호를 붙여서, 받는 쪽이 순서대로 처리하고 같은 메시지는 한 번만 처리한다. 메시지는 로비 영역(방, 대기방)과 게임 영역(진행)으로 나뉜다.

### 클라가 같은 규칙으로 계산하는 처리
통행료, 월급, 파산, 세무조사, 적립금, 무인도, 3연속 더블, 턴 전환, 황금열쇠 효과는 알림 없이 **호스트 판정과 같은 규칙**으로 각 클라가 반영한다. 규칙을 바꿀 때는 호스트와 참가자 코드를 같이 고친다. (호스트와 참가자는 공용 `Rules/` 코드를 쓴다)

### 검증 순서 (방장이 요청을 받을 때)
1. 진행 중인 게임이 있는가
2. 땅 번호가 있다면 존재하는 땅인가
3. 요청자의 차례인가
4. 파산하지 않았는가
5. 요청이 현재 단계에 맞는가
6. 제한 시간 안인가
7. (구매·건설·인수) 요청자의 말이 그 땅 위에 있는가
8. 기능별 검증 (현금, 소유자, 건설 가능 여부 등)

검증이 하나라도 실패하면 상태는 바뀌지 않고 요청자에게만 오류를 보낸다.

### 사람 구분과 재접속
- 사람은 두 가지 번호로 구분한다. **연결 번호**는 Photon이 접속할 때마다 새로 붙이는 번호이고, **게임 번호**는 게임과 방 안에서 그 사람을 가리키는 번호다. 처음 들어온 사람은 두 번호가 같고, 방장 PC의 사람 기록(`PlayerRegistry`)이 둘의 대응을 기억한다. 닉네임은 구분에 쓰지 않아서 같은 이름이 둘 들어와도 된다.
- 같은 사람인지는 **PlayFab 계정(ID)** 으로 알아본다. Photon이 PlayFab에 확인한 사용자 ID라서 남이 흉내 낼 수 없다. 끊겼다가 새 연결로 들어와도 그 계정이 이 게임의 참가자면 예전 게임 번호를 이어서 쓴다.
- 요청의 보낸 사람은 메시지에 적힌 연결 번호로 정한다. (Shared 모드의 수신 콜백은 보낸 사람이 아니라 받는 사람 번호를 알려 줘서 쓸 수 없다.) 번호를 바꿔 적은 요청을 막지는 않는다. 친구끼리 하는 용도라 허용한다.
- 게임 중에 연결이 끊긴 사람은 방에서 빼지 않고 **자리를 남기며**, 방장이 바로 AFK로 표시해 자동으로 진행한다. 게임이 끝날 때까지 안 돌아오면 그때 방에서 정리한다.
- **자동 재연결:** 게임 중에 끊기면 게임 화면에 머문 채 화면을 어둡게 덮고, 같은 방에 3초마다 최대 30초 동안 다시 들어가 본다. 성공하면 방장이 자리를 돌려주고, 화면이 현재 상태를 받아 이어진다.
- **대기방 자동 재연결:** 대기방에서 끊겨도 로비로 나오지 않고 같은 방에 같은 방식(3초 간격, 최대 30초)으로 다시 들어가 본다. 방장이 받아 주면 화면이 방을 다시 그린다. 방이 사라졌거나 게임이 이미 시작됐으면 바로 로비로 나온다. 방장이었다면 남은 사람 중 한 명이 방장을 이어받았으므로 나는 게스트로 들어간다. 방에 나 혼자였다면 방이 사라져서 돌아올 수 없다.
- **이어하기:** 자동 재연결에 실패하거나 앱을 껐다 켠 경우를 위해 마지막 게임 방 코드를 이 기기에 저장해 두고, 로비 방 목록에 `[이어하기]`로 보여 준다. 게임이 끝나거나 일부러 방을 나가면 지운다.
- 한계: 이어하기는 이 기기에 저장된 방 코드를 쓰므로 **다른 기기에서는 진행 중인 게임을 이어할 수 없다.** 모든 사람이 동시에 끊기면 방이 사라지고, 사람이 혼자(봇만) 있는 방은 그 사람이 끊기면 사라진다. (사람이 없는 방을 살려 둘 이유가 없어서 의도한 동작이다)

### 방장 승계
- 방장이 나가면 다음 사람이 마스터가 되고 호스트 역할(규칙 판정, 봇, 시간)을 이어받는다. 방은 끝나지 않는다.
- 대기방에서는 새 방장이 마지막으로 받은 방 정보로 방을 복원하고, 이미 나간 사람은 뺀다.
- 게임 중에는 모든 클라이언트가 같은 규칙으로 게임 상태를 따로 계산해 가지고 있어서, 새 방장이 **자기 화면의 상태를 복사해서 호스트를 시작**한다. 화면이 받은 알림을 모두 반영하고 입력을 기다리는 때까지 최대 8초 기다리고, 시작한 직후 **모든 사람에게 현재 상태를 다시 보내** 화면을 맞춘다. 새 방장 PC가 게임을 처음부터 새로 시작하지는 않는다.
- 호스트만 알던 값은 이렇게 이어받는다. 제한 시간은 새로 시작한다. AFK 표시는 처음부터 다시 시작하고 나간 사람만 바로 표시한다. 처리 중이던 요청은 이어받지 않고, 상태를 받은 화면이 다시 입력을 기다린다.

### 오프라인 모드 (혼자 하기)
- Photon이나 PlayFab에 연결하지 못하면 (인터넷이 없음, AppId가 없음, 처음 연결이 12초 안에 안 됨, 연결됐다가 끊긴 뒤 30초 동안 다시 시도해도 안 됨) 이 PC 안의 호스트로 도는 혼자 하기로 전환한다. 잠깐 느린 것을 연결 실패로 보지 않으려고 끊긴 뒤에는 오래 기다린다. v1.0.1과 같은 동작이다. 타이틀로 돌아가면 다시 온라인을 시도한다.
- 오프라인에서는 PlayFab에 접속하지 않으므로 전적을 기록하지 않는다.
- 로비 헤더의 연결 표시: 초록 "서버 연결됨", 노랑 "연결 중, 재연결 중", 빨강 "오프라인 (혼자 하기)". 로비 연결이 끊기면 스스로 다시 연결한다. (한 번에 12초까지 기다리고, 안 되면 3초 간격으로 다시 시도)

### 계정과 전적
- 처음 실행하면 익명 계정이 자동으로 만들어진다. 닉네임은 PlayFab 표시 이름으로 저장한다. 표시 이름은 3~25자이고 겹칠 수 없어서 `닉네임#계정ID 끝 4글자`(예: 철수#716C)로 저장하고, 겹치면 뒤 글자를 늘린다. 화면에는 `#` 앞의 닉네임만 보인다.
- **이메일 계정:** 타이틀의 "이메일 로그인 / 가입"에서 한다. 가입은 지금 쓰는 계정에 이메일을 붙이는 것이라 ID, 닉네임, 전적이 그대로다. 로그인은 이미 가입한 계정으로 바뀌고, 이 기기를 그 계정에 연결해서 다음부터 자동으로 로그인된다. 이때 이 기기에서 쓰던 익명 계정은 이 기기와 연결이 끊기므로 안내를 보여 주고 한 번 더 누르게 한다. 이메일은 한 계정에 한 번만 붙고 바꿀 수 없다.
- **가입 2단계:** 인증 코드 입력은 PlayFab에 없어서(서버 코드가 필요하다), 메일에서 비밀번호를 정하는 방식으로 이메일 주인을 확인한다.
  - 1단계 "이메일 인증": 이메일만 넣고 누르면 아무도 모르는 임시 비밀번호로 이메일이 계정에 붙고, PlayFab이 비밀번호를 정하는 메일(재설정 메일, 영어)을 보낸다.
  - 사용자가 메일의 링크에서 비밀번호를 정한다. 그 주소의 주인만 할 수 있어서, 없는 주소나 남의 주소로는 다음 단계를 끝낼 수 없다.
  - 2단계 "가입 완료": 게임으로 돌아와 정한 비밀번호를 넣으면 그 이메일로 로그인이 되는지 확인하고 가입이 끝난다. 그다음 닉네임을 넣고 시작한다.
  - 1단계 뒤 앱을 닫아도 이어 가려고 이메일과 그때의 PlayFab ID를 이 기기에 저장하고, 타이틀 링크가 "가입 이어서 하기"로 바뀐다. 계정이 바뀌거나 서버의 이메일이 다르면 저장한 값을 버린다.
  - 이메일을 잘못 넣었다면 이메일은 바꿀 수 없으므로 "새 계정으로 시작"한다. 지금 계정의 기록이 이 기기에서 사라지므로 안내를 보여 주고 한 번 더 누르게 한다.
  - 이미 쓰는 이메일로 1단계를 하면(다른 기기에서 시작한 가입을 이어 갈 때, "새 계정으로 시작"한 뒤 같은 이메일, 이미 가입을 끝낸 이메일) 막지 않는다. 비밀번호를 정하는 메일을 보내고 카드를 "이미 있는 이메일" 모양(로그인 모드)으로 바꿔서, 정한 비밀번호(이미 있다면 그 비밀번호)로 로그인하게 한다. 로그인하면 그 이메일이 붙은 계정으로 바뀐다. 가입 기다림은 이 기기에 저장하지 않는다. 기다림 저장은 그 기기에만 있고 이메일은 PlayFab 계정에 붙어 있어서, 다른 기기에서는 이 방법으로 이어 간다.
- 비밀번호 찾기는 PlayFab이 보내는 재설정 메일을 쓴다.
- **전적:** 플레이 횟수(`Games`)와 승리 횟수(`Wins`)를 PlayFab 통계로 기록한다. 결과 창이 "승리"로 보여 주는 사람(파산하지 않은 1등)을 승리로 센다. 온라인 방이면 봇과만 한 판도 기록한다. 올리지 못하면 이 PC에 보관했다가 다음에 올린다. 로비의 내 카드에 `28승 20패 (58%)`로 보여 준다. 클라이언트가 자기 통계를 올리는 방식이라 조작할 수 있다.

## 6. 게임 규칙

### 기본 설정

방장이 대기방에서 바꿀 수 있는 값은 인원, 봇 수, 초기 자금, 최대 라운드, 월급 다섯 가지다. 나머지는 고정이다.

| 항목 | 기본값 | 방장 변경 |
| --- | --- | --- |
| 인원 | 2~4명 (사람 + 봇) | 가능. 봇 수와 사람 수의 합이 인원을 넘을 수 없다 |
| 초기 자금 | 1,000,000 | 가능 (200,000 / 300,000 / 500,000 / 1,000,000 / 2,000,000) |
| 월급 | 150,000 | 가능 (50,000 / 100,000 / 150,000 / 200,000 / 300,000) |
| 최대 라운드 | 20 | 가능 (10 / 15 / 20 / 30 / 40) |
| 세무조사 세금 | 100,000 | 고정 |
| 무인도 영업정지 | 3턴 | 고정 |
| 입력 제한 시간 | 60초 | 고정 |
| 보드 | 32칸, 땅 23개 | 고정 |

### 경제 규칙

| 항목 | 규칙 |
| --- | --- |
| 투자금 | 땅값 + 지금 단계까지 지은 건물 비용 |
| 매각가 | 투자금 × 50% |
| 인수가 | 투자금 × 200% |
| 통행료 | 땅 단계별 값 (땅, 별장, 빌딩, 호텔). 주인이 없으면 0 |
| 건설비 | 올라갈 단계 한 번의 비용 (누적 아님) |
| 총자산 | 현금 + 가진 땅의 투자금 합계 |
| 월급 | 출발 지점을 지나거나 도착하면 지급. 세계여행 이동 중 통과도 지급. 무인도 이동과 뒤로 가는 카드는 지급 안 함 |
| 세무조사 | 현금 한도 안에서만 걷고, 걷은 금액은 적립금에 쌓임 |
| 적립금 | 적립금 칸 도착 시 쌓인 금액 전액 지급 |

- 금액 계산은 **정수 연산**으로 한다. (원본 C#의 `long × 0.5f`는 정밀도 한계가 있음)
- 인수 후에도 건물 단계는 유지되고 주인만 바뀐다.

### 통행료 흐름
1. 현금 ≥ 통행료: 주인에게 이체. 이체 후 현금 ≥ 인수가면 인수 선택, 아니면 턴 종료
2. 현금 < 통행료이고 현금 + 전체 매각가 ≥ 통행료: 매각 선택 후 이체, 턴 종료 (매각 뒤 인수 선택 없음)
3. 전부 팔아도 모자라면 파산: 땅을 매각가로 현금화해 전액을 땅 주인에게 넘기고, 땅은 주인 없음 + 땅 단계로 초기화. 더블이어도 다음 플레이어로 넘어간다.

### 특수 칸과 규칙

| 항목 | 규칙 |
| --- | --- |
| 무인도 | 도착하면 영업정지 3턴, 턴 강제 종료. 영업정지 중 더블이 아니면 남은 턴 -1하고 이동 없이 종료. 더블이면 해제되고 그 더블로 이동 (추가 턴 없음). **남은 턴이 0이 된 뒤 더블은 일반 더블로 처리** (서버 이식 때 고친 버그) |
| 3연속 더블 | 3번째 더블이면 이동 없이 무인도로 (월급 없음) |
| 세계여행 | 다음 턴이 목적지 선택으로 시작. 세계여행 칸 자체는 목적지로 고를 수 없음. 도착 후 더블이어도 턴 넘김 |
| 건설 불가 땅 | 독도 등 관광지는 건설 없이 땅 기준 통행료 |
| 황금열쇠 | 보너스, 벌금, 지정 칸 이동, N칸 이동, 무인도. 카드는 매번 전체 중 무작위 |

### 턴 단계
굴리기 대기 → (도착 칸에 따라) 구매 / 건설 / 인수 / 매각 / 카드 / 목적지 대기 → 턴 종료. 요청 하나가 흐름을 끝까지 처리한 뒤 끝난 단계만 저장한다.

### 게임 종료와 등수
- 종료: 생존자 1명 이하이거나, 다음 라운드가 최대 라운드를 넘을 때
- 파산한 사람의 등수는 파산 시점의 생존자 수 (4명 중 첫 파산 → 4위)
- 생존자는 총자산 → 현금 → 원래 턴 순서로 등수 부여

## 7. 입력 제한 시간, AFK, 봇

- 사람 차례는 제한 시간(기본 60초) 안에 입력이 없으면 호스트가 대신 진행하고 AFK로 표시한다.
- 봇 차례는 6초 뒤 호스트가 진행한다.
- AFK인 사람은 다음부터 8초만 기다리고 대신 진행한다. 요청을 보내거나 재접속하면 AFK가 풀린다. 연결이 끊긴 사람은 방장이 바로 AFK로 표시한다.
- 화면의 선택창은 호스트의 대기 시간보다 먼저 닫힌다. (일반: 화면 50초 / 호스트 60초, AFK: 화면 5초 / 호스트 8초) 호스트가 먼저 움직이면 화면과 겹쳐 입력이 거절되므로 이 순서를 유지한다. 그 사이 10초와 3초는 연출이 늦어지는 시간과 네트워크 지연을 덮는 여유다.
- 시간 값(봇 6초, AFK 8초, 화면 여유 10초와 3초)은 코드의 `TimeRules` 한 곳에서 정하고, 호스트와 화면이 같은 값을 쓴다. 화면 여유는 호스트와 화면 사이의 시간 오차를 덮으려고 정한 값이라, 특별한 문제가 없으면 바꾸지 않는다.
- 대신 진행(제한 시간 초과, AFK)과 봇은 **같은 전략**이 구매·건설·인수·매각·세계여행 목적지를 판단하고, **사람과 같은 처리 함수**를 호출한다. 거절도 반드시 같은 경로로 호출해야 턴이 멈추지 않는다.
- 봇 판단: 구매·건설·인수는 ① 통행료 위험 → ② 가치 판단 → ③ 기회비용을 모두 통과해야 진행. 매각과 세계여행 목적지도 전략이 고른다. (판단 기준값은 `BotSettings`로 분리)

| 화면 | 내용 |
| --- | --- |
| 타이틀 | 닉네임 입력, 시작, 이메일 로그인 / 가입(이메일 인증, 가입 완료, 비밀번호 찾기). 가입 중이면 가입 이어서 하기, 이메일 계정이면 로그아웃 |
| 로비 | 서버 연결 표시, 내 전적 카드, 방 목록(새로고침, 이어하기, 방 상세의 참가자 이름), 방 만들기(방 이름 입력), 입장, 코드로 입장 |
| 대기방 | 준비, 방장 설정(초기 자금, 월급, 라운드, 인원, 봇 수), 채팅, 방 코드(눌러서 복사. 브라우저가 막으면 코드만 보임). 방장이 나가면 다음 입장자가 방장이 되어 설정과 시작 권한을 이어받는다 |
| 인게임 | 주사위·말 이동, 구매·건설·인수·매각 팝업, 세계여행 선택, 카드, 턴 타이머 |
| 결과 | 등수 표시 후 같은 멤버로 대기방 복귀 |
| 설정 | 로비와 인게임에서 여는 팝업(같은 프리팹). 배경음과 효과음 값을 저장한다. 소리 파일과 사운드 시스템은 아직 없다. 언어 선택 줄(한국어, English)이 있고, 로그인(타이틀) 화면에도 설정 버튼이 있다 |

## 10. 위험 요소

| 위험 | 대응 |
| --- | --- |
| 방장이 나가면 게임이 멈춤 | Shared 모드의 마스터 자동 승계(입장 순서)를 쓰고, 새 방장이 자기 화면 상태로 호스트 역할을 이어받는다. (5장 방장 승계) |
| 웹에서 탭이 뒤로 가면 연결이 끊기고, 방장이면 자동 진행이 늦어짐 | 브라우저가 뒤로 간 탭의 실행을 멈추고 Photon은 약 10초 넘게 신호가 없으면 연결을 끊는다. 앱이 막을 수는 없어서, 탭이 돌아오면 대기방과 게임 중 모두 같은 방에 자동으로 다시 들어가게 했다. 방장이 혼자 있는 방은 사라진다. 방장은 게임 탭을 앞에 두거나 Windows(.exe)를 쓰도록 안내한다. (exe는 창이 뒤로 가도 계속 실행된다) |
| 재접속 때 같은 사람인지 알아봐야 함 | PlayFab 계정으로 확인한다. 이메일을 붙이지 않은 계정은 그 기기에서만 알아볼 수 있고, 브라우저 저장 데이터를 지우면 새 계정이 된다 |
| 큰 메시지가 Photon 호출 한도(약 512바이트)를 넘음 | 신뢰할 수 있는 데이터 전송(reliable data)을 쓴다. (구현 완료) |
| 웹 빌드에서 Photon과 PlayFab 요청이 막힐 수 있음 | v1.1 웹 빌드에서 막히지 않는 것을 확인했다. 브라우저나 배포 환경이 바뀌면 다시 확인한다 |
| 웹에서 한글 입력이 안 됨 (해결, v1.1.2) | Unity 웹 빌드가 브라우저 한글 입력기(IME)의 조합 입력을 입력칸에 전달하지 못한다. 입력칸 위에 투명한 HTML 입력칸을 겹쳐 브라우저가 조합을 처리하고 글자를 Unity 입력칸에 넘긴다. (`WebIMEInput`) 웹 빌드에서 확인했다. 화면의 커서는 Unity 입력칸의 것이라 글자 중간을 고칠 때 위치가 맞지 않을 수 있고, 모바일 브라우저는 확인하지 않았다 |
| 웹에서 방 코드 복사가 안 됨 (해결, v1.1.2) | Unity 웹 빌드가 시스템 클립보드를 지원하지 않는다. 보이지 않는 textarea를 선택해 브라우저에 복사를 시킨다. (`WebClipboard.jslib`) 웹 빌드에서 확인했다. Safari와 모바일은 확인하지 않았고, 브라우저가 막으면 코드를 화면에 보여 주는 안내로 대신한다 |
| 정적 글꼴이 커짐 | 정적 글꼴 2개가 각각 약 34MB(4096x4096)다. 글자판을 다시 만들 때마다 저장소가 그만큼 커지므로 필요할 때만 만든다. 정적 글꼴에 없는 글자는 동적 대체 글꼴(Pretendard)이 그린다 |
| 동적 대체 글꼴 에셋이 Git에 변경으로 계속 잡힘 | 에디터에서 실행하거나 빌드하면 대체 글꼴이 그린 글자가 에셋에 저장된다. 플레이를 멈출 때, Unity에서 다른 프로그램으로 넘어갈 때, 에디터를 종료할 때 글자판을 자동으로 비운다. (`FallbackFontTools`) 그래도 잡히면 `git update-index --skip-worktree`로 숨긴다 |
| 영문화 범위가 큼 (해결, v1.1.3) | 코드 안의 한글 문자열 약 1,000개(로그와 개발용 창 포함)와 씬과 프리팹의 UI 글자 약 280줄이 한국어로 박혀 있었다. 번역표와 언어 전환을 먼저 만들고 화면별로 나눠 옮겼고, 빠진 글은 점검 스크립트로 찾는다. 조사가 섞인 문장은 문장 단위로 다시 쓰고, 영어는 글자가 길어 칸을 넘칠 수 있어 칸 크기로 계산해 줄였다. 에디터에서 영어로 한 판을 확인하고 v1.1.3으로 배포했다 |
| 방장이 직접 조작하면 치팅 가능. 참가자가 다른 사람 번호로 요청을 보내거나 전적을 올리는 것도 막지 않음 | 친구끼리 하는 용도라 허용. 배포 범위를 넓힐 때 다시 검토 |
| 사람이 혼자(봇만) 있는 방은 끊기면 사라짐 | **그대로 둔다.** 사람이 없는 방을 계속 살려 둘 이유가 없다 |
| 이메일을 잘못 넣고 가입 1단계를 하면 이메일을 바꿀 수 없음 | 없는 주소는 비밀번호를 정할 수 없어서 가입을 끝낼 수 없고, 그때는 "새 계정으로 시작"한다. 고친 클라이언트가 1단계만 하고 건너뛰는 것은 막지 못한다(코드 입력 방식도 마찬가지라 오타 방지용이다) |
| 외부 서비스(Photon, PlayFab)에 의존 | 정책, 요금, 한도가 바뀔 수 있어 대시보드에서 확인한다. 연결되지 않으면 오프라인(혼자 하기)으로 전환된다 |
| 비밀 키 노출 | PlayFab Secret Key와 Photon의 secret 값은 코드와 저장소에 두지 않는다. Photon AppId 설정 파일도 저장소에서 제외했다 |
| 호스트와 참가자의 규칙 계산이 어긋남 | 규칙을 `Rules/`로 모아 호스트와 클라가 같은 코드를 쓴다. 개발 중에는 상태 비교 로그(`HostStateCheck`)로 어긋남을 잡는다 |
| 서버 이식 때 고친 버그가 되돌아옴 | 이 문서의 규칙표와 원본 서버 구현을 기준으로 직접 플레이해 확인하고, 호스트와 클라 상태 비교 로그로 어긋남을 잡음 |
| 무료 한도 초과 | 20 CCU면 약 5방. 한도에 닿으면 접속이 막히므로 대시보드에서 확인 |
| 원본 라이선스 | 원본 레포에 라이선스 파일은 없지만, 원작 팀이 사용에 문제없다고 확인함 (공개 배포 완료) |
